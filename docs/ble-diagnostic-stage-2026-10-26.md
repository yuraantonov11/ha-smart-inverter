# BLE-інтеграція RWB1 — робоча версія етапу (2026-10-26)

## Статус

BLE-канал працює як **діагностичний**: cloud лишається єдиним джерелом для
HEMS, SOC, планувальника та керування. Жодне BLE-значення не підключене
до керування.

- Репозиторій: `/opt/data/powmr-ai-work/powmr_inverter`, гілка `develop`
- Робоча версія: `4ea835e` («BLE: запис бюджету й teardown поза event loop»)
- Живий HA: `192.168.1.220`

## 1. Живий блок на головному дашборді

Дашборд **«Smart Solar Енергопанель»** (`powmr-energy`), секція 2 у вкладці
«Огляд» — блок **«Bluetooth · показники інвертора»**:

- напруга мережі, напруга батареї, SOC, PV, навантаження;
- плитка «Джерело даних» → `sensor.rwb1_ble_data_source`:
  стан `Bluetooth` / `Bluetooth · застаріло` / `Bluetooth · немає даних`;
- у тексті блоку: час останнього успішного отримання (київський),
  вік даних («останні 30 с») і явна позначка застарілих даних.

Значення оновлюються автоматично: сенсори перезаписуються кожного циклу
читання, Lovelace перерисовує плитки за зміною стану — перезавантаження
сторінки не потрібне.

**Технічні лічильники** (`read_status`, сесії, помилки, спроби, proxy)
лишаються в окремій секції «BLE діагностика».

Важлива деталь реалізації: дашборд збережено через websocket
(`lovelace/config/save`), а не прямим записом файлу. Зовнішня зміна
`/config/.storage/lovelace.powmr_energy` оновлює лише сховище — HA
продовжує віддавати фронтенду стару конфігурацію з пам'яті.

### Чи знадобилося автоматичне recovery

**Ні.** Після рестарту:

- `recovery.state = idle`, `attempts = 0`, `last_attempt_at = null`;
- адресного DISCONNECT не виконувалося — проксі сам відпустив застрягле
  з'єднання, коли зник підписник API (RWB1 почав advertising знову).

Тобто штатне закриття **ще не підтверджене**: `disconnect` не завершився,
але канал відновився без допомоги. Адресне автоматичне відновження
перевірене вживу окремо — успішне звільнення 2026-10-26 10:18:28 UTC на
проксі `54:EF:44:CF:32:16 / Gateway BT Proxy / 192.168.1.146:6053`.

## Лічильники звільнень

`recovery.releases_total` рахує **спроби** адресного звільнення, а не
успішні. Поточне значення 3:

| № | час | результат |
|---|---|---|
| 1 | 10:18:28 | успішно: `released D4:27:87:E4:F9:4F on the proxy 54:EF:44:CF:32:16 / Gateway BT Proxy / 192.168.1.146 / port 6053` |
| 2 | ~14:00:51 | невдача: `APIConnectionError: Not connected to gw3-btproxy @ 192.168.1.146!` → бюджет вичерпано |
| 3 | ~14:33 | спроба в епізоді після рестарту; стан повернувся в `idle` |

Поточний бюджет епізоду: `attempts=0 / max_attempts=3 / cooldown_s=300` —
скидається успішним читанням, переживає reload і рестарт
(`/config/powmr_ble_recovery.json`).

## Відкриті пункти

1. **Blocking I/O виправлено, але ще не в роботі.** `4ea835e` переносить
   записи бюджету й teardown в `hass.async_add_executor_job`. У живому HA
   ще крутиться попередня версія: там 220 попереджень
   `Detected blocking call to write_text` з дампом traceback на один
   захват (~7 МБ логу). Виправлення на диску HA вже є, але набуде чинності
   лише з наступним рестартом.
2. **`field_diagnostics.py:209`** — блокуючий `open(..., "ab")` поза межами
   BLE-частини; окремий дефект того самого класу, не змінювався.
3. `disconnect` не завершується при штатному закритті — потребує окремого
   розбору ( bleak_esphome / проксі).
4. `rwb1.py` лишається byte-identical: md5 `7d3c6719c8951c89dd0b1c99314cb7b0`,
   5561 B.

## Верифікатор наступного циклу

`scripts/verify_restart_cycle.py` — єдиний інструмент наступного планового
рестарту:

- без `--restart` — dry-run: читає журнал зупинки, запис teardown і стан
  читань, рестарту **не** робить;
- з `--restart` — один рестарт HA, потім ті самі три перевірки і окремий
  вердикт «recovery ЗНАДОБИВСЯ» / «recovery НЕ знадобився».

Виправлено після першого прогону: `recovery.last_result` може бути `None`
(спроб звільнення ще не було) — падіння на `.get('proxy')`; і знімок БД тепер
валідується: пара DB+WAL може бути неузгоджена, тоді SQLite або помиляється
«database disk image is malformed», або бере рядки без атрибутів. Неузгоджений
знімок перетягується ще раз (до 6 спроб).
